<h1>Краткое описание утилиты</h1>
Утилита для анализа погруженности сотрудников в функционал. 

<h2>Отображает следующую информацию:</h2>

- Список функционала высокого уровня, для которого у нас есть тесты:
  - <details><summary>Для функционала отображается следующая информация:</summary>
    
    - Количество кейсов пройденных каждым из сотрудников
    - Количество кейсов, созданных каждым из сотрудников
    - Общее количество кейсов в функционале
    - [TODO] Количество пройденных уникальных кейсов
    </details>
  - <details><summary>Для сотрудников, без привязки к функционалу, отображается:</summary>
    
    - Суммарное количество пройденных за все время кейсов
    - Суммарное количество созданных за все время кейсов
    </details>

- Подробный список функционала на всех уровнях: 
  - <details><summary>Для функционала отображается следующая информация:</summary>
    
    - Количество кейсов пройденных каждым из сотрудников
    - Количество кейсов, созданных каждым из сотрудников
    - Общее количество кейсов в функционале
    - [TODO] Количество пройденных уникальных кейсов
    </details>
  - <details><summary>Для сотрудников, без привязки к     функционалу, отображается:</summary>

    - Суммарное количество пройденных за все время кейсов
    - Суммарное количество созданных за все время кейсов
    </details>
Устаревшие кейсы в анализе не учитываются и не будут отражены в сводной таблице погружения сотрудников. 
Так же, в таблице не будут отображены директории, в которых на всех уровнях вложенности есть только устаревшие тесткейсы.

<h3>Дополнительная информация о тесткейсах</h3>
Для тесткейсов, использованных в анализе, отдельно отображаются следующие данные:

- Список ниразу не пройденных кейсов
- Список кейсов с неизвестным автором
- Список устаревших кейсов

Все тесткейсы в указанных списках перечислены в иерархии их родительских директорий, повторяющей таковую в ТМС. ID тесткейса - гиперссылка на него в ТМС.
Если при составлении списка не было обнаружено ни одного кейса, который мог бы быть к нему отнесен, то список не отображается, как таковой.
Если не отображается ни один из списков, то не отображается и блок "Для информации"

<h1> Конфигурирование </h1>

Есть возможность конфигурирования списка сотрудников, результаты анализа погружения которых будут отображены.
Данный список находится в файле `/src/main/resources/config.yaml`. Будут отображены результаты анализа погружения только незакомментированных сотрудников, перечисленных в ключе `relevantMembers` указанного yaml конфига.
Независимо от значения ключа `relevantMembers`, анализ погружения проводится для всех сотрудников, кто проходил или создавал кейсы в проекте. Указанный конфиг влияет только на отображение данных.
В этом же конфиге можно указать адрес ТМС, данные авторизации и ID проекта, кейсы которого будут использоваться для анализа

Пример конфига:

```YAML
relevantMembers:
  # Список участников проекта, для которых будет проведен анализ погружения
  - member1
  - member2

tmsData:
  #Данные TMS
  address: "https://allure-testops.org/"
  auth: "AUTH_token"
  projectId: 1
```
